# Dictate — push-to-talk dictation (AssemblyAI streaming)

Vision + feature spec: `PROJECT-VISION.md`. Single-user Windows tray app, Python + tkinter.

## System map
| Piece | File | Notes |
|---|---|---|
| Entry / controller | `main.py` | tk mainloop owns UI; other threads post commands via `App.request()` queue. DPI awareness set before `tk.Tk()` — don't remove, the pill mispositions without it |
| Mic + WAV | `audio.py` | 16 kHz mono int16; WAV written in the audio callback — recording never depends on the network |
| Streaming | `stream.py` | `wss://streaming.assemblyai.com/v3/ws`, `speech_model=assemblyai-stt-3-7-realtime`, `language_codes` repeated in query string (verified accepted). Optional `prompt` (config key, empty = omitted) is *context describing the audio*, never an instruction — AssemblyAI drops behavioral/formatting commands. NB: attr is `_stop_evt`, not `_stop` (Thread shadows `_stop`). The server sends NOTHING during silence, and the connect `timeout=10` also applies to `recv()` — so `WebSocketTimeoutException` in the recv loop is benign (a thinking pause), never a failure. **Drops:** the server sends an `Error` message then a close frame (code + reason — table: assemblyai.com/docs/streaming/common-session-errors-and-closures); both are logged as `stream dropped: close <code>: … (<error>)` — `recv()` discards close frames, hence `recv_data_frame(True)`. A drop mid-take **reconnects** (≤3×, never on 1008 = auth/billing/rate-limit): the whole take is kept in `self.audio` and resent from the last word of the last *ended* turn, so nothing is lost or doubled; partial-turn words are never `word_is_final`, so there's no earlier safe point. Measured: the server transcribes at real time however fast audio arrives (2× = no gain, a burst just queues), and STT-3.7 turns run 20 s+ with `end_of_turn` arriving seconds late — so a drop usually leaves a 10-30 s backlog that trails the take. At stop, backlog ≤ `MAX_STOP_WAIT` (10 s) is waited out and delivered normally (`ok_reconnected`, drop reasons in the log row's `error`); more than that → `abort()` + the async retry. Test harness: replay a WAV and kill/poison the socket mid-take (`ws.send("[]")` forces a real 3006 close) |
| Hotkey | `hotkey.py` | WH_KEYBOARD_LL hook suppressing ONLY the exact combos + Esc-while-recording. NOT `keyboard.add_hotkey(suppress=True)` (eats the Win key) and NOT RegisterHotKey (Win+Ctrl+Space is OS-reserved, registration fails). Explicit ctypes argtypes required — defaults truncate 64-bit handles (err 126). Several combos via `extra=[(hk, cb)]`; they are matched **most-modifiers-first**, because a superset combo (Win+Ctrl+Shift+Space) also satisfies the subset's `_mods_held` and would otherwise fire the plain hotkey |
| Overlay pill | `overlay.py` | click body or ✓ = done, ✕/Esc = cancel (cancel STILL saves + logs audio), mode badge bottom-left toggles live/paste. Calm by design: solid dot, log-scaled fixed-reference waveform (see feedback_calm-ambient-ui memory). Silence auto-stop (`main._check_silence`): after `silence_autostop_secs` of no voice (default 150, 0=off) the take auto-finishes normally, EXCEPT an empty auto-stopped take logs `ok` (not `stream_failed` — no pointless retry); last 60 s the pill grows an amber countdown band, body-click there = "I'm here" (resets timer), ✓/✕ keep their meaning. Voice detection MUST be adaptive — webcam AGC holds a silent room at RMS ~290, so fixed cutoffs see 100% voice: floor = p10 of last 30 s, voice = 3 consecutive chunks > max(2.5·floor, floor+120) (clicks are 1-2 chunks, never reset). Tune against saved WAVs with a chunk-RMS sim, not live. Live hold: static amber `N held — go back to resume` in the bottom-right slot (no flashing); after a take whose held text wasn't typed, `show_note()` shows a 5 s amber note (click dismisses) |
| Delivery | `inject.py` | clipboard+Ctrl+V (waits for hotkey keys released) or live `keyboard.write`. **Live = hold and resume** (`main._type_pending`/`_tick`; config `live_hold`, default true, tray checkbox; off = `_on_target()` always True, i.e. type wherever focus is): `start_recording` remembers the foreground window (`inject.foreground_window()` — windows of our own process read as None, so the pill is never the target; None → first outside window gets adopted). Each turn is typed only if the target is foreground right then, else it's HELD in order; only while something is held, `_tick` polls the foreground every 100 ms and spawns `_flush_held` when the target is back. All typing serializes on `_type_lock`, and `_type_pending` no-ops once `recording` is False (the untyped rest is `_finalize`'s tail). At stop: target foreground (or our own window, e.g. the pill after a ✓ click, with nothing held) → type held+tail; else type nothing — the clipboard holds the whole take either way. Checks windows, not caret (same-window other text box still gets text — accepted). Rejected: refocusing the target to type (interleaves with user keys), WM_CHAR/UIA background injection (Chrome/Electron ignore it). `apply_voice_commands`: spoken "new line"/"new paragraph" → breaks, only when punctuation-set-off (pause), so sentences about newlines survive. `remove_fillers`: regex um/uh/erm removal + punctuation/capitalization repair (no LLM); config `remove_fillers` (default true), checkbox in log window; log.jsonl always keeps raw text |
| Log & recovery | `logstore.py`, `gui.py`, `retry.py` | `recordings/log.jsonl`; Retry = async `/v2/transcript` — body takes `speech_models` (PLURAL list of full names, currently `["assemblyai-stt-3-7", "universal-2"]`; bare/deprecated names 400, and the 400 body names the replacements — `_req` surfaces it). A `stream_failed` take auto-retries this path from `main.py` and puts the result on the clipboard (never pastes/re-types — focus may have moved) |
| Tray | `tray.py` | pystray, runs detached. Right-click IS the menu and left-click runs the `default=True` item — a new action can only be a menu entry, never its own mouse binding. Menu labels spell out the matching hotkey (read from config, so it can't drift) |
| Hebrew-only take | `main.py` (`toggle_he`, `start_recording(langs=…)`) | One-shot monolingual take from `hebrew_hotkey` (Win+Ctrl+Shift+Space) or the tray entry: `language_codes=["he"]` for THAT take only, via a copied `take_config` — nothing is saved, so the next normal press is multilingual again and no mode can be left on. Per AssemblyAI docs a single-element `language_codes` **is** the monolingual mode (`language_detection` only controls per-turn *reporting*). Pill shows a blue `HE ONLY` badge, tray tooltip says `(he only)`, and log.jsonl records `langs` per take. Caveat: if the stream drops, the async recovery in `retry.py` still auto-detects — it does not force Hebrew (`transcribe_file` accepts `language_codes` and ignores it). **Measured (2026-08-26, two saved Hebrew WAVs replayed through the real socket): `["he"]` alone is the whole fix — everything came back in Hebrew script. An English-language contextual prompt describing the audio as Hebrew made it WORSE (English phrases reappeared); the same prompt in Hebrew changed nothing. So `HEBREW_PROMPT = ""` — don't "help" it with a prompt without re-running that A/B (`prompt` is plumbed through and off).** English spoken inside a Hebrew-only take comes out as Hebrew-script nonsense — that is the mode working, not a bug |

## Ops
- Run: `pythonw main.py` (singleton via port 51733). Autostart: shortcut in `shell:startup`.
- **Restart with `pythonw main.py --restart`** — graceful takeover via the singleton socket (port 51733 doubles as control channel): the old instance finishes any in-flight recording (saved + logged, no paste), quits, and the new one takes the port. Never Stop-Process. (Verified: takeover during an active take waited for it to finish.)
- Log rows are written at recording START (`status: recording`) and updated at finish — a crash leaves the row stuck, and `logstore.recover_orphans()` at next startup repairs the WAV header, flips it to `recovered`, and pops the log window for Retry. (Verified with a deliberate mid-take kill.)
- Debug log: `app.log` (rotating not needed; small). Test scripts pattern: feed a WAV into `StreamSession` with a `queue.Queue` at 50 ms pacing.
- Costs money while streaming ($0.45/hr) — keep test clips short.
- **Live tests share the user's real app**: `--restart` cancels an in-flight take, synthetic hotkey presses toggle THEIR recording, and temporary config changes affect their next dictation. Get an explicit go-ahead ("mic free?") before any of those, and restore config + restart promptly after.
